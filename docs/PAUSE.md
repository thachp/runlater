# Durable default-queue pause/resume (local prototype)

`GET /v1/queue` returns the tenant's durable `paused` flag with its existing limits. `PUT /v1/queue` uses the existing `configure` permission and full configuration object; `paused` must be an explicit boolean. Read and replace the current configuration to preserve other settings. Old stored snapshots default to unpaused, but omitted `paused` in new API writes returns400 so an older client cannot implicitly resume a paused queue. Configuration writes are serialized by the tenant Durable Object; concurrent writers remain last committed writer wins, without ETags or compare-and-swap.

Pause gates **new claims**, including already queued references and due retries. Enqueue remains available subject to normal admission limits, and accepted payloads/idempotency records remain durable. A reference rejected because of pause is acknowledged as a durable deferral; the authoritative ready ledger/alarm resumes publication later. There is no independent transport retry loop for pause. The gate runs before token spending, lease/fence creation or callback execution. If claim committed first, an in-flight callback may still execute or finish; pause cannot undo its effect or refund its rate token. Result commits, fencing, cancellation and lease reconciliation remain active.

A pump that reads paused state emits no references. A publication already in progress when pause commits may still finish sending its references; the authoritative claim gate prevents them from starting callbacks. Ready and scheduled/retry due times do not produce a one-second alarm/publication loop. Wakeups remain for running lease expiry, delivery-age expiry, terminal retention, audit retention and diagnostic retention. A watchdog armed by a command may fire once to normalize the next deadline. Further operator commands can legitimately arm another watchdog; the claim is bounded idle behavior, not zero alarms under ongoing requests.

The existing one-day delivery-age budget runs from `initial_due_ms`, including time paused; pause never extends it. Nonrunning work becomes failed when server time is strictly later than `initial_due_ms + 86400000`; the corresponding alarm is due at the next millisecond. A running callback retains its lease/result semantics, including uncertain-outcome handling on lease expiry. Resume reconciles expired paused work and durably re-arms eligible work without changing task ID, generation, attempt history or age budget. Terminal tasks stay terminal. Failed work needs the separate explicit redrive path and permission.

Identical configuration does not append a configuration event or refill the rate bucket. Ordinary command maintenance can still reconcile expired work. Pause/resume alone preserves the bucket's raw token/time state; normal elapsed-time accrual is applied at the next claim, capped by configured burst. A rate/burst policy change accounts for elapsed time under the old rate before adopting the new policy; increasing burst does not mint a new burst.

`GET /v1/queue/health` labels the snapshot with `paused`. Its backlog counts remain observational due/stored-state counts, not dispatchable work or provider Queue depth. Pure queue/health/metrics queries never reconcile tasks, refill tokens, save SQLite or update alarms. Fixed metric categories `claim_paused` and `paused_age_expired` distinguish paused claim references and age expiry without starting another attempt from attempt outcomes; they are not billing or delivery counters.

The local example client's `pause()`/`resume()` helpers read then replace configuration, so require both read and configure permissions and have the same last-writer-wins limitation. Configure-only callers can submit an explicit complete configuration directly.

## Evidence and limits

`tests/pause.rs` covers both claim/pause orderings, old/stale Queue references, retry identity/budgets, in-flight completion, lease expiry/fencing, cancellation/retention, exact age boundaries, future schedules, restart, legacy snapshot default, idempotent configuration, token accounting and pure reads using deterministic server-time inputs.

`npm run test:pause-local` uses the compiled Rust test Worker with real local workerd/SQLite/alarm/Queue dispatch. Private service-binding barriers hold a reference before claim and a completed fixture callback before its durable result, exercising both orderings without an API fault route. It also holds an already-started publication across pause to verify that its eventual reference cannot claim. It checks paused publication/pump bounds, pure SQL/schema/alarm reads, restart, tenant/permission isolation, cancellation, retry due while paused and identity-preserving resume. A stopped, owned disposable SQLite fixture is seeded with an old due timestamp to test actual runtime alarm age expiry: elapsed time is simulated, not a day-long test. No unrelated local state is edited. The wrapper restores the default artifact and checks that private runtime hooks are absent.

This is offline prototype evidence, not proof of live Cloudflare concurrency, external effects, arbitrary destination safety, billing/credits, capacity or production operations. No live resources, secrets, DNS, production credentials or payment changes are included. Launch gates remain in #7/#11.
