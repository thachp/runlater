# Agent discovery source contract

Issue26 adds static discovery source, not a public API or registered tool executor. Run `npm run build:discovery` to assemble `build/discovery/landing` and `build/discovery/docs` from the existing static site source plus canonical discovery/quickstart/OpenAPI files. No network/provider call, DNS mutation or hosting occurs. Future static hosting must use those assembled roots. REST/OpenAPI remains canonical; generated local task inputs and the byte-identical OpenAPI copy are tested against docs/openapi.json.

The intended landing path `/runlater-service.v1.json`, descriptor schema, tool metadata/schema, pricing-status schema and Markdown quickstart use RunLater-owned custom formats and version1.0.0. They are not an industry discovery protocol, MCP registration or an authorization grant. No reserved `.well-known` registration is claimed. The llms.txt filename follows the [community proposal](https://llmstxt.org/), not a security standard. Every planned-host link is validated offline against its assembled file, not asserted to resolve publicly. Source links target the repository; host roles remain landing/docs/API as planned.

Readiness is explicit: hosted tasks/authentication are unavailable; arbitrary HTTPS delivery is disabled; callback rotation is an offline design library. Three task tools describe only the canonical loopback fixture API. Registration, entitlement, quote and purchase tools are disabled nonbinding proposals with null REST bindings. Public-key/proof encodings and algorithms are intentionally not chosen by these illustrative string schemas; issue27 must define them before any executable registration contract. Numeric schema bounds are representation limits, not commercial trial/price/credit offers. Pricing has null commercial values, no payment methods, no live purchases or auto-top-up. No MPP implementation or compatible wallet is claimed.

Discovery carries untrusted information. A client must apply its own parsing, provenance, permission, user delegation and wallet safeguards; metadata cannot override them. Credential transport belongs to an already authorized client, not tool arguments. Scheduling authority never implies purchase authority. There are no executable tool handlers or automatic network/payment actions in this slice. Changing a disabled capability requires an implementation, versioned schema/metadata review and separate activation authorization.

See [next bounded implementation plans](AGENT-NEXT.md) for production-mode identity and entitlements. Functional API deployment still requires reviewed production authentication and registered-destination/runtime safety; no readiness-only substitute is chosen or deployed here.
