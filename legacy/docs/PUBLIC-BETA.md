# Public free beta — source implementation, not activated

This mode uses open Ed25519 proof of possession, not operator invitations. It is separate from the retained restricted-alpha Worker. No production master, resources or domain changes have been made by this source increment. The machine contract is `contracts/public-beta-v1.json`.

## End-to-end flow

1. Generate your own Ed25519 key locally. POST the public key to `/v1/registration/challenge` and sign its exact `canonical_utf8` bytes. POST challenge ID and signature to `/v1/registration/complete`. Only a valid proof can allocate a permanent cohort slot or touch a derived project object. The fixed registry has at most32 expiring pending challenges.
2. Completion atomically creates an immutable global grant reservation. The project atomically installs identity and funding. A lost response or interruption between these objects is recoverable by repeating completion during its five-minute window, or obtaining a fresh challenge with the same key afterward. The original seven-day grant and100 attempt units are returned; recovery never starts another trial. Key possession is not personal identity or Sybil resistance.
3. Sign POST `/v1/callback-key` with body `{}` and a fresh nonce/idempotency key. The result is the project's own HMAC verifier key, served with `Cache-Control: no-store, private`. Treat it as secret: possession also permits forging that project's callbacks. The master is never returned or stored in project snapshots. Different projects/releases derive different keys. Signing keys are separate from the bot's Ed25519 API key.
4. Deploy your receiver at an exact `https://worker.account.workers.dev/path`. Configure only your derived key and the one-use private ownership proof returned by destination prepare. You have five minutes to install the proof and call verify. Never expose the proof via an unauthenticated installation route. The verification request does not include the expected secret response, so an echo endpoint cannot pass. Ownership is not a general SSRF guarantee.
5. Create a task referencing the verified registered endpoint. The project atomically snapshots destination version, callback protocol/body/operation identity, reserves the full finite attempt budget and creates the task. Actual alarm/outbox/Queue claims spend fenced units before global HTTPS fetch; result settlement precedes acknowledgement. Duplicate transport references cannot spend another unit for the same fence. At-least-once callbacks require receiver-side durable operation deduplication.

## Explicit limits

First cohort:10 lifetime projects, no automatic reset or refill. Each project gets seven days to admit tasks and100 internal attempt credits, with five units reserved per fresh task/redrive. There is also a stricter16-task lifetime admission ceiling and128-publication lifetime ceiling.100 credits do **not** promise100 tasks. Cancellation, retention, replay, expiry or restart does not reset the16 admissions. Tasks must be due by trial expiry; already funded accepted work can finish afterward under its unchanged retry-age budget. API identity access expires after seven days. No payment, automatic recharge or public renewal path exists.

The registry permits512 anonymous challenge/completion operations per release,24 per minute, and1000 authenticated ingress operations per project. Once exhausted it fails closed; operator review is required, and accepted tasks continue via transport. These are finite application limits, not a Cloudflare billing hard cap. Distributed anonymous requests, signed replay and Queue duplicates can still consume edge/DO reads. The first cohort can be exhausted by multiple keys held by one person.

Cloudflare per-location IP limits are6 registration requests/minute and60 general requests/minute. Trusted `CF-Connecting-IP` is parsed and HMAC-hashed with release/day domain separation; raw IPs are not persisted or logged. These rate bindings are abuse mitigation, not globally exact quotas or identity. Global capacity is serialized durably in the fixed registry. Queries do not reconcile project task state; separate registry admission observations may count signed reads.

## Network boundary

Only exact two-label managed Workers.dev receiver hosts are enabled. No custom domains, account roots, IP literals, userinfo, non443 ports, query strings or fragments. The service's own configured Workers.dev host and RunLater hosts are excluded. Proof and callbacks use the reviewed bounded global Fetch adapter, manual redirect rejection,3second timeout,1KiB response and32chunk bounds; no VPC/service binding or `resolveOverride` for customer URLs. Deployment MUST retain `global_fetch_strictly_public`. This is reliance on Cloudflare's public global-Fetch isolation plus a narrow managed-host beta policy, not DNS pinning or proof of arbitrary customer-host safety. Local interception tests cannot establish provider runtime network isolation. A reviewed controlled live proof remains necessary before opening registration.

## Revocation and activation

`BETA_REVOKED_PROJECTS` is an operator-owned bounded list. Mutating registry routes persist revocation; omission on later configuration cannot resurrect a revoked grant. Queue routing propagates revocation to the project before delivery. In-flight effects cannot be recalled. Changing master material conflicts with persisted material identities and fails closed; this first beta does not implement automated master rotation. Keep the master until all accepted work/verifier overlap has ended. Emergency project revocation and disabling new public ingress remain separate from accepted-task maintenance.

`beta/wrangler.example.jsonc` is disabled and has no domain route. Source-only proposed resources: dedicated `runlater-public-api`, fresh `AdmissionRegistry` and `InvitationProject` SQLite namespaces, `runlater-public-ready` Queue, two rate bindings. Existing alpha/sites/secrets stay intact. Before activation obtain specific approval to generate and retain **one** `BETA_CALLBACK_MASTER` secret in the dedicated API Worker; it authorizes deriving every beta project's callback key. No receiver receives this master or a namespace binding. Pin reviewed SHA, account baseline, actual Workers.dev self-host, immutable release dates, callback signing validity through last grant+retry age+verification overlap, and exact domain handover/rollback. Preserve global/project storage across redeploys: a new namespace/release is a new cohort and must not silently reset budget.

The total RunLater budget remains US$20/month, without a provider hard cap. Do not upgrade plans or introduce services/payments. New live campaign/rollout requires parent release and resource ownership inventory; this config is not an executable authorization. Stop and reconcile unexpected usage. Keep paid observability disabled and log metadata only, never payloads, proof responses, key material, signatures, IPs or raw receiver responses.
