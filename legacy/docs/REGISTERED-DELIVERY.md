# Restricted registered delivery — offline source, not activated

This source increment wires the production project aggregate to a controlled, operator-owned HTTPS receiver. It advances functional readiness; it does not activate api.runlater.io or provide open registration, arbitrary destinations, payments or customer delivery. The previous real staging phase2 HTTP400 remains unresolved until a new reviewed Cloudflare diagnostic proves this path. Local Fetch interception cannot prove DNS, TLS, deployed secret handling or provider billing.

## Exact boundary

Production accepts fresh tasks only when `ALPHA_DELIVERY_ENABLED=operator-approved`, explicit approved identity and finite grant policies exist, the dedicated Queue binding is present, and fresh callback material is available. The default configuration remains closed. This alpha accepts only `registered:<configured endpoint ID>` with JSON body at most 1,024 bytes and `synthetic:true`. The only permissible URL is `https://receiver-alpha.runlater.io/callback`. No caller URL, IP literal, userinfo, query, alternate port, custom auth headers or redirects are allowed. This is a fixed owned endpoint, not arbitrary customer-host SSRF/DNS-rebinding protection.

The authoritative project snapshot v3 includes registration, immutable acceptance endpoint revision/URL, callback-v2 policy/body/operation identity, key material fingerprints (never material/signatures), lifetime admission/publication counters and bounded per-attempt protocol/key-ID/category diagnostics. Old v2 funding snapshots decode without writing on GET; this deployment requires a fresh namespace, since old fixture tasks have no delivery registration.

New enqueue/redrive validates and commits task, full funding reservation and registration atomically in the same row. Replay/cancel retains the original task identity and accounting. Every new retry selects the current active key at dispatch, rather than snapshotting a secret at enqueue. Same key ID cannot silently change material. Key IDs/history cannot be removed, backdated into an earlier revision, extended or un-revoked. Operator policy sync durably applies grant/endpoint/key revocation independently of failed task admission, before the configuration is considered applied. Redeploying older policy fails closed. Endpoint revocation is irreversible for this alpha endpoint; recovery requires a reviewed new identity/migration rather than resetting history.

The alarm maintains durable eligible rows as outbox. A watchdog is armed before business mutation or Queue I/O; publications reserve durable budget before an uncertain send. Final re-arm preserves future schedule, lease/age/retention work. Failed sends explicitly re-arm. The Queue consumer calls the project DO; lease/fence/unit spending and key selection persist before Fetch. Duplicate/stale references do not dispatch. After Fetch the handler reloads state so cancellation/config/lease recovery during I/O cannot be overwritten. Result/terminal settlement persists before acknowledgement; uncertain handler/results retry transport. Cancellation/revocation cannot undo a request already in flight. The five-attempt/age budgets remain authoritative.

Fetch uses POST, exact signed bytes, JSON content type, manual redirects (all rejected), a 3-second abort deadline, at most 2,048 response-header bytes and 1,024 response-body bytes/32 chunks. Read-scoped task queries expose only fixed delivery categories, fence, protocol and nonsecret key ID. Known bounded receiver error codes map to fixed categories; raw response content is discarded. No raw response, payload, signature or credential is logged/persisted in diagnostics. HTTP failures, timeout/network uncertainty and policy/size/redirect failure use fixed categories. No synthetic success fallback exists in the API.

Hard source bounds per project lifetime: 16 accepted tasks and 128 publication reservations. They never reset on cancel, retention, restart or redeploy. Exhausted publication budget stops publication and preserves age/lease/retention wakeups, eventually recording ordinary failure/settlement rather than a busy loop. `max_retries=1` is a transport setting, not a proof of at most two deliveries. Bad/missing operator configuration pauses publishing; due active work has at most a 60-second recovery wake, future work waits until due, and terminal-only history waits until retention; it does not refund accepted work or extend its retry age. Configuration must be corrected or the controlled campaign torn down promptly.

## Receiver

`alpha/receiver/worker.mjs` is synthetic and side-effect-free. It never proxies or runs user actions. It bounds route, headers, body and read time; checks v2 HMAC locally before accessing the project DO; then checks the same namespace's durable registration/key/endpoint state through a private binding. A stale receiver deployment holding old material cannot override durable revocation. Timestamp overlap is at most the existing five-minute v2 window; key cutover and verifier overlap remain separate. The receiver intentionally supports synthetic error/redirect/size/timeout cases for diagnostics. Retry behavior uses the authoritative attempt number, not a caller header or ephemeral counter. Repeated valid callbacks can return a receipt but perform no business side effect; a real customer receiver still needs durable operation-key deduplication.

No public API route exposes the DO's deliver/verify methods. The receiver binding grants the **full project namespace capability**, not a provider-enforced verify-only capability. This reviewed same-boundary synthetic receiver uses it only for verification. It must never be given to a customer receiver and requires specific activation approval. Both Worker secret slots hold the same dedicated JSON key-material bundle. Only key IDs/digests enter durable API state.

Publication-exhaustion regression: nonrunning work now age-terminalizes during background reconciliation even while unpaused, so settlement precedes re-arm and cannot repeatedly schedule an already-past age deadline. The compiled regression seeds elapsed age/publication exhaustion only in an owned stopped SQLite fixture, restarts workerd, and runs the actual alarm; it does not wait a day or inject a remote fault hook.
